# 简短回答与截断恢复

## 参数与行为

- 默认提示词目标：150～250 字，心理咨询先一句回应感受，再给最相关的 2 条建议，必要时一个追问。
- 简单问候不凑字数；用户明确要求详细说明时可展开；高风险安全规则优先。
- `CHAT_ANSWER_MAX_TOKENS=1024` 只控制最终回答，不提高意图识别等内部 Agent 的预算。
- `CHAT_CONTINUATION_MAX_TOKENS=512` 控制补完收尾，原有 120 秒生成时间预算包含续写。
- 字数是提示词目标，不是硬截断；Token 与汉字不是一一对应。

## 截断判定

统一客户端读取 Spring AI Generation 元数据中的结束原因，保留 OpenAI usage-only 尾帧之前的 finish reason。
`length` / `max_tokens` 触发 `OutputTruncatedException`，观测记录为 `TRUNCATED`；不能仅凭输出 Token 达到上限推断截断。
未返回结束原因时显示未知，维持原有传输完成判定，不声称已经验证语义完整性。
流式传输保留空白片段，避免 Markdown 和句子之间的空格/换行被过滤。

## 有限续写

1. 初次回答被明确截断时，在短数据库事务内占用本轮唯一一次续写额度。
2. 发送 `continuation` SSE 事件；前端显示补完提示，保留已显示文字。
3. 使用已冻结的原始提示词、已输出回答和收尾指令继续生成，不重新执行 Agent、检索或注册报表/邮件任务。
4. 续写指令只允许补完当前句子/建议并尽快收尾，不重复、不新增话题或标题。
5. 完整结束后合并为一条回答，再按原有逻辑写 MySQL 正常消息和 Redis 会话记忆。
6. 续写再次被截断、为空或失败时标为 `FAILED`，错误说明“回答未能完整收尾”；不保存半段正常历史，提供重新生成。

`chat_messages.continuation_count` 保存已占用次数，网络恢复或自动重试不重置。
只有用户明确点击重新生成、进入新 generation 时重置；旧数据的 null 按 0 读取。
续写可能仍有重复文字，提示词不能保证语义去重；不采用可能误删有效句子的字符串裁剪。

## 观测与验证

首次输出阶段为 `FINAL_RESPONSE`，续写为 `FINAL_CONTINUATION`；各自有独立耗时、Token 和结束原因。
`GET /api/chat/replies/{requestId}` 返回 `continuationCount`。
测试覆盖两种服务商结束原因、使用 1024 预算、尾帧用量、续写一次成功/再次截断/网络失败，以及断线恢复时额度不重置。
