# 后台记忆改造验收（2026-10-22）

## 改造结果

- 请求准备阶段只写入持久化记忆任务，不同步抽取长期画像。
- MemoryAgent 复用已有摘要；无摘要时用近期原文，不再每轮调用摘要模型。
- 摘要按照覆盖位置增量更新，默认新增 6 条待摘要消息或 3000 字符触发，最新 6 条原文保留。
- 后台全局单工作者，聊天有执行租约时不领取任务，聊天结束空闲 2 秒后处理。
- 画像任务按用户来源顺序推进；提交时校验任务租约与已处理位置，索引另行重试。
- 增加管理员任务面板与失败重试接口；模型观测将维护调用标为 `MEMORY_BACKGROUND_*`。

## 四类场景

| 场景 | 自动化验收 | 真实部署验证 |
| --- | --- | --- |
| 连续对话 | 第二轮模型输入保留第一轮事实；前台没有摘要/画像模型调用；达到阈值才生成增量摘要 | 考试焦虑 → “今晚先做哪一步”两轮 SUCCESS，第二轮读取 Redis 中两条历史并接续回答 |
| 后台模型或索引失败 | 画像模型失败进入 RETRYING/FAILED，聊天仍 SUCCESS；索引失败不回滚已保存画像 | 小模型返回不规范字段，任务按上限重试后 FAILED；加 JSON Schema 后通过管理接口重试成功，原对话始终 SUCCESS |
| 连续改变偏好 | 详细 → 简短；旧任务人工重跑被标记 SKIPPED，不能覆盖新状态 | 同一画像 ID=3 从“希望回复详细”更新为“希望回复简短”，后续索引任务均完成 |
| 断线/重启 | 客户端取消并恢复后仍只有一组 PROFILE/SUMMARY 任务；替换工作者后接管过期租约，旧持有者禁止提交 | 暂停后台消费者，完成两轮并确认四个 PENDING 任务落库；重建应用容器并启用消费者，任务继续执行，未重复创建 |

租约到期/旧持有者防覆盖使用集成测试模拟，真实容器验证覆盖的是待处理任务跨进程恢复。实际测试没有故意关闭所有用户共用的模型服务。

这些是不同输入的单次观测，不能据此计算提速百分比。首条咨询的主要耗时仍是 Supervisor（5.931 秒）、知识环节超时调用（1.240 / 2.704 秒）和最终生成（4.330 秒，含生成到完成），不是后台记忆抽取。两轮咨询测试为验证持久化恢复，临时暂停了后台消费者；后两轮偏好测试启用了正常后台处理。

最终版本追加验证的前台画像 Embedding 调用耗时 4.927 秒、Supervisor 调用 7.589 秒。长期画像的读取/召回仍在前台，此次移动的是画像抽取和摘要生成；不能把首字延迟问题描述成已经全部解决。该轮后台成功保存“偏好使用中文回复”，证据为输入中的完整原句，索引 SUCCESS，摘要因不足阈值 SKIPPED。

## 测试与证据

- 回归范围：聊天恢复、Agent loop、SSE、模型观测、模型服务商用量、网络取消、回答规划及记忆维护，共 61 项；其中本次记忆验收 9 项。
- 额外检查：管理员接口权限、前端脚本语法、变更格式、应用健康状态。
- 真实测试原始记录：本地 `data/deploy/20261022-background-memory/` 中的 `live-before-restart.json`、`live-after-restart.json`、`live-preferences.json`、`final-smoke.json`、`automated-tests.json`。
- 升级前备份：同目录 `mysql-before.sql`，旧镜像 `mindharbor-agent:before-background-memory`。这些本地数据不提交到仓库。

真实测试暴露的结构化输出问题已补充 JSON Schema；另外拒绝无法在用户原文中找到的画像证据，并用自动化用例验证。试验期间生成的一条不符合证据要求的模拟画像已通过正常删除接口清理。

## 使用与限制

打开本地页面 `http://localhost:8080/`，管理员登录后查看“后台记忆维护”。状态 SKIPPED 通常表示未达到摘要阈值或任务已过时，不代表失败。

前台优先目前是领取任务时的准入控制，不能抢占已经运行的本地模型计算；持续高负载时后台维护可能延后。本次没有改变路由、风险判断和知识检索的必要前台步骤，也不保证所有咨询都能在一两秒内返回首字。

实现及参数详见 [后台记忆维护](background-memory.md)。
