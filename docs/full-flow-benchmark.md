# 1,000 条真实模型全流程验证

## 测试边界

从 PsychQA synthetic 原始输入中固定选取 1,000 条，四类各 250 条。其中 240 条来自先前留出测试集、760 条来自训练集。这是工程链路测试，不是独立泛化准确率评测；数据集情绪标签也不等于项目的意图/风险等级。

实际执行 HTTP/SSE、Agent 调度、检索、模型回答、MySQL 检查点、Redis、后台画像/摘要/索引、报告及远程 MCP Excel。普通聊天和低风险场景按照真实路由跳过不适用步骤。邮件使用 LOG 模式；测试实例和 MCP 实例均没有真实邮件密钥，外部投递地址被禁用。

测试账号、数据库、Redis、Chroma 与 Excel 独立；模型使用当前本机 Ollama `qwen2.5:1.5b` / `bge-m3`。先导两组各五轮，主批次九十九组各十轮，以覆盖摘要更新。每轮等待后台任务达到终态，再发送下一条。这不是高并发压力测试。

## 先导测试发现与修复

初版实际提交了八条，暂停前完整采集七条。聊天回答和 Excel 写入成功，但八条画像任务均出现 JSON 解析失败；不能用聊天 SUCCESS 宣称全流程通过。

### 画像结构化生成

- 抓取隔离实例的真实 Ollama 请求，确认输出重复了错误 JSON 结构，直到 1,000 Token 上限。
- `Map.of` 构造的字段顺序不稳定；字符串的否定字符类正则在当前本地结构生成链路中也出现兼容问题。
- 同一失败输入对照验证：固定字段顺序并移除该正则后，模型约 92 Token 正常结束。此为单样本因果排查，不能推广为整体提速比例。
- 改为固定 `type → key → value → ...` 的字段顺序，与提示词示例一致。字段内容、长度、标点、来源证据仍经过 `MemoryFactPolicy` 校验。
- `completeWithin` 也检查终止原因，`length` 明确抛出 `OutputTruncatedException`，不把截断内容视作完整 JSON。
- 不提高 Token 上限，不把缺失画像伪装成成功，也不删除失败证据。

### Embedding 冷启动

- 实测第一次加载约 3.8 秒，加载后同类请求约 41 毫秒；前台预算只有 1.2 秒，取消请求会妨碍冷模型加载完成。
- 在同一 Ollama 地址上启用独立异步预热；首次启动以及调用失败后可触发，单工作者、每分钟最多一次、最多等待 30 秒。
- 只使用固定预热文本；不对其他远端供应商自动发起预热。预热观测单独标记 `EMBEDDING_WARMUP`。
- 仍保留前台检索超时与 BM25 降级，不让当前学生请求等待 30 秒。
- 可用 `EMBEDDING_LOCAL_WARMUP_ENABLED=false` 关闭。预热失败不等于检索服务已恢复，后续仍需查看实际调用结果。

## 证据与运行

### 日常求助的路由复核

先导数据还发现“我总觉得自己比别人差、开心不起来、需要支持”的输入被判为 CHAT。补充了日常自述困扰规则，提升为 CONSULT 后交给 RiskGuardian 评估，不直接把它判为 HIGH；同时对引用、假设、第三人称、否定句与技术语境添加反例验证。

进一步发现“帮我、如何、为什么”等通用词曾触发普通任务快捷路由，现已从快捷规则删除；补充间接危险表达检测，并为引用、假设、否定和第三人称添加反例。高风险标签样本若仍被分到 CHAT，批次会暂停供复核，标签本身不等同于临床风险结论。

风险评估提示词另行明确普通焦虑、持续低落与危险信号的区别：避免单凭心跳快或社交紧张推断危险意图。三个原始路由失败样本在修复后真实复测为 CONSULT/LOW、RISK/HIGH、CONSULT/LOW；这不代表已经验证所有表达。报告单独列出路由和风险标签差异，供人工复核。

40 条先导结果及补充复测保留在独立证据目录。正式 1,000 条使用最终版本和新的隔离数据库，避免混合版本统计；正式结果不包含这些先导次数。

画像、预热、内部截断处理、回复恢复、检查点、知识检索与路由相关自动化回归累计 175 项通过。真实批量测试的进度和最终结果以本地报告为准，不能用自动化通过数量替代 1,000 条完成数量。

本地输出目录：`data/benchmarks/full-flow-20261023/`（Git 忽略）。

- `before-fix/`：修改前原始结果与数据库证据。
- `manifest.json`、`samples.json`：版本、抽样、会话分组与输入哈希。
- `results.jsonl`：每条首字/回复/后台耗时、步骤、模型用量、失败与降级记录。
- `summary.json`、`report.md`：当前完成数量与统计；未满 1,000 条明确标记未完成。
- `database-evidence.json`：工具、记忆、模型和 Agent 记录。
- `excel-verification.json`：在批次静止后校验工作簿可读、报告 ID 缺失和重复。运行中比对可能存在快照时间差。

运行脚本只连接隔离实例 `localhost:18080`。每条使用固定 requestId，支持读取已保存结果后继续。修复前后使用不同数据库，防止旧失败任务与新结果混在一起。断点发生在未记录完的请求时，需要先检查其服务端状态；复用 requestId 是重放已有结果，不能把它当作重新执行的性能样本。

```powershell
node scripts/run-full-flow-benchmark.cjs --limit=10
node scripts/run-full-flow-benchmark.cjs --ranges=11-30,61-70 --stop-on-failure
node scripts/report-full-flow-benchmark.cjs
powershell.exe -NoProfile -File scripts/verify-benchmark-excel.ps1
```

修复后先导验证通过后，才将 `pilot-acceptance.json` 标为 PASS 并启用后续批次。后续新增失败会暂停，而不会盲目跑完 1,000 条。

## 耗时口径

- **首字等待**：HTTP 发起到收到第一个实际 token。
- **完整回复**：HTTP 发起到流结束。
- **含后台完成**：直到画像、摘要、索引及相关报告工具到达终态，包含失败重试。
- **Agent 耗时**：按实际执行次数统计，重入单独计数。
- **模型调用耗时**：按阶段统计成功、超时与失败；与 Agent 耗时有包含关系，不能重复相加。
- **RAG 子步骤**：读取轨迹中的改写、缓存、召回、联合评审；召回已包含缓存查询。没有独立计时的数据不虚构均值。
- **Token**：仅累计供应商报告用量，另列缺失数量。

正常对话测试不替代进程崩溃、租约接管、旧任务覆盖和浏览器断线的故障注入测试；相关自动化验收应单独列出。
