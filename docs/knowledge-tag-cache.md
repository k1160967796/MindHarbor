# 三标签精确知识候选缓存（第一版）

> 2026-10-20 新增独立的已审核知识包直用分支，见 [reviewed-knowledge-packs.md](reviewed-knowledge-packs.md)。
> 本文“始终评审”仅指普通候选缓存；候选不会自动升级为已审核知识包。

## 实现范围

支持以下三个背景 / 情绪 / 表现组合：

| 标签 | 固定公共检索 query |
|---|---|
| 考试 / 焦虑 / 入睡困难 | 快考试了很焦虑，晚上睡不着怎么办 |
| 考试 / 焦虑 / 注意力难集中 | 快考试了很焦虑，书看不进去、注意力难集中怎么办 |
| 学业任务 / 焦虑 / 拖延启动 | 作业快截止了很焦虑，拖延不敢开始怎么办 |

通过保守词表映射明确表达（例如“紧张”归入该缓存的焦虑类、“睡不着”归入入睡困难），
不新增模型调用，不做语义向量缓存；这是一种检索分类，不是心理诊断。
缺情绪、多个背景/表现、否定、复杂/反复/加重、方法无效、当前或近期风险、
假设/第三人称问题等绕过。词表不可能涵盖所有自然语言，必须保留每轮评审及风险评估。
没有匹配的情况正常走现有 RAG，而不是猜标签。

## 执行顺序

1. 原有按需查询改写保留。标签只从本次明确输入提取，模糊追问不跨用户缓存。
2. 查 Redis：`mindharbor:knowledge:tags:v1:<boot UUID>:<generation>:<三标签>`。
3. 命中：按 ID 回读 MySQL 候选，检查发布状态和正文/来源指纹，不调用混合召回。
4. 未命中：使用固定公共 query 召回候选，不把学生原话用于填充共享候选池。
5. 始终结合当前学生原问题、记忆执行联合评审。
6. 只有完整、非降级召回且评审 SUFFICIENT/REVIEWED 才写缓存，保存评审前公共候选。
7. 标签候选评审为 PARTIAL/NONE/UNKNOWN：在剩余预算内对原检索问题执行正常召回并再次评审。
   即使没有 retryQuery 或 query 没变化，也允许这次回退；不再额外开启第三次召回。
   时间预算耗尽时保留不足/未知状态，不谎报充分。
8. 保留最终 materialize 源数据校验、RiskGuardian 和个性化回复。

缓存只含知识块 ID、评分及正文/来源 SHA-256 指纹。
不保存学生 ID、学生原话、画像、风险判断、个性化回答或前一个学生的评审结果。

## 生命周期

- `KNOWLEDGE_TAG_CACHE_ENABLED`：默认 true，可关闭以恢复原链路。
- `KNOWLEDGE_TAG_CACHE_TTL_SECONDS`：默认 1800 秒，写入时设置，命中不续期。
- 支持的知识写入入口 `ingestBlocks` / `approve` 在事务提交后切换 generation；
  回滚不切换。旧 generation 的并发查询不能填充新版本缓存。
- 命中还会回读候选并校验指纹，拒绝被删除、待审核或修改过的片段。
- 首版以单应用实例为部署范围，跨学生共享，不跨应用实例共享。
  重启后命名空间变化，避免复用旧模型/配置生成的缓存；旧键由 TTL 回收。
- 直接用 SQL 修改知识库不属于支持的写入入口：新增资料不会主动旋转 generation，
  应通过项目入库接口更新，或重启/等待过期。
- Redis 不可用、格式错误、写入失败时走原流程；仍受现有 Redis 连接超时约束。

## 观察与验证

KnowledgeAgent 轨迹新增：

- `cache=MISS_STORED`：首次召回充分，写入缓存。
- `cache=HIT`：复用候选，仍执行本轮评审。
- `cache=HIT_REJECTED`：本轮评审不足/未知，删除缓存并尝试正常检索。
- `cache=BYPASS_*`：不符合缓存条件。
- `cache=ERROR`：缓存不可用，直接按原问题召回。
- `cacheTag`、`cacheLookupMs`：标签与读取耗时。
- 原有 `recallMs` 包含首轮缓存检查/召回；`reviewMs` 是首轮评审耗时；
  `elapsedMs` 才包含补查回退总耗时。不能将首次阶段之和当作含回退的总时间。

手动试用：分别在两个新会话发送

1. “我明天考试，太焦虑了睡不着怎么办”
2. “临近考试很紧张，入睡困难怎么办”

仅当首轮召回正常且评审充分时，第二次才预期 HIT；若模型评审超时、知识不足或
依赖失败，不会强制写缓存。不要在同会话用“还是”“上次的方法”等追问验证命中。
这只省去 KnowledgeAgent 的查询向量化/混合召回，不会省掉长期记忆向量召回、
联合评审或最终模型生成。

自动化测试覆盖候选跨学生复用、每轮独立评审、风险不被跳过、保守标签分类、
无建议改写时仍回退、Redis 故障、内容变更/撤回/删除、事务提交与回滚、
旧版本并发写入、TTL 配置和重启隔离。单元测试调用次数不等于真实端到端加速比。

## 2026-10-20 本地服务验证

`KnowledgeTagCacheLiveTests` 为显式开启的独立探针，使用真实本地 Ollama
（qwen2.5:1.5b / bge-m3）、Chroma 和 Redis，读取旧 MindBridge 数据库中的
47 个知识块作为只读快照。Repository 使用快照，因此不包含常规 JDBC 查询耗时。
不启动完整聊天业务，不创建学生消息/报告，不发送邮件；结束时删除该探针自己的缓存键。
通过 `KNOWLEDGE_CACHE_LIVE=true` 才执行，普通测试默认跳过。
可用 CACHE_PROBE_DB_URL / CACHE_PROBE_DB_USER / CACHE_PROBE_DB_PASSWORD /
CACHE_PROBE_COLLECTION 指定本地测试来源，勿将真实密码写进命令或提交。

第一次用书面化标准 query 时，评审不足导致缓存未写入，反而重复检索。
改用上表中的自然语言固定公共 query 后，睡眠组合得到一次 MISS_STORED、连续三次 HIT：

| 模式 | 首轮召回/缓存阶段 | 查询 Embedding / recall 调用 | KnowledgeAgent 总耗时 |
|---|---:|---:|---:|
| 未缓存（模型预热后，首个样本） | 89 ms | 1 / 1 | 1095 ms |
| 首次填充（含 Redis 首次建连） | 399 ms | 1 / 1 | 2534 ms |
| HIT 1 | 8 ms | 0 / 0 | 1093 ms |
| HIT 2 | 3 ms | 0 / 0 | 1082 ms |
| HIT 3 | 3 ms | 0 / 0 | 958 ms |
| 未缓存（同句对照） | 50 ms | 1 / 1 | 974 ms |

结论：该样本验证了候选复用能减少检索调用和阶段耗时；联合评审占主要时间，
少量样本的整体耗时没有稳定改善。不能宣称网页首字延迟下降某个百分比，
也不能把本次单一组合的结果推广到所有场景。
原始观测在 `target/knowledge-tag-cache-live.json`；
初版未命中观测在 `target/knowledge-tag-cache-live-initial.json`。

上述测量阶段没有更换旧应用容器或迁移数据库；源码/测试完成不代表网页已加载新版本。
当前源码 Compose 项目/服务名是 MindHarbor；旧 MindBridge 实例升级需保留原持久化配置，
以容器内 JAR、健康状态及页面接口确认新版生效，具体迁移注意事项见 README。
