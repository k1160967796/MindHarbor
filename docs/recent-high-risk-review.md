# 近期高风险上下文复核

## 修复的问题

同一会话先说“我想死”，下一句说“作业太多了写不完”。原分类器因“作业”直接返回 CHAT，旧 RouteGuard 又要求当前句必须是“那怎么办”等特定追问，导致跳过风险评估。

## 当前处理

1. RouteGuard 在 CHAT 放行前检查同一会话最近 **3 条用户历史消息**。只使用 user 原始内容，不使用助手回复、系统提示词或生成摘要作为风险事实。
2. 其中出现现有高风险词库命中时，升级为 CONSULT，轨迹记录 `RECENT_HIGH_RISK_REVIEW`。不要求当前句满足追问正则，换话题也不直接解除复核。
3. CONSULT 继续执行 KnowledgeAgent、RiskGuardian、Counselor。不会额外增加一个路由模型调用；风险评估仍是已有 RiskGuardian 的一次调用。
4. RiskGuardian 使用 previousHistory 原始历史和独立的当前输入进行评估，避免 modelHistory 截断丢失复核依据。轨迹增加 `recentHighRisk=true/false`。
5. 提示词明确：解释压力来源、不再重复危险词或换话题不代表风险解除。近期风险下调必须额外返回布尔值 recentRiskResolved=true，并在 resolutionEvidence 逐字引用本轮输入中的缓解依据（至少 4 个字符）。后端检查字段类型和原文出处；缺失或捏造依据则保守维持 HIGH。具备依据的评估可以下调，路由不永久锁定 HIGH。
6. 模型失败、非法 JSON 或缺失 emotion/risk 标签时，若近期存在高风险信号，保守返回 HIGH，报告摘要标明复核不可用，不能伪装成模型成功评估。

## 边界

- 3 条是本次工程复核窗口，不是临床上的风险解除标准，也没有新增持久化风险个案状态机。旧信号离开窗口不代表已经证明风险解除。
- 仍使用现有关键词规则，不能保证识别所有隐晦表达，也可能将引用、否定中的关键词当成信号；语义判断质量需要另行评估。
- 缓解依据校验能检查模型是否引用真实输入，不能单靠字符串校验证明该内容确实代表安全，也不能替代人工复核。
- 复核后沿用既有报告与工具链；若最终为 HIGH，仍可能触发新的报告/预警，本次未增加跨轮通知去重。
- 不涉及不同会话之间的风险状态继承。正常无近期高风险历史的作业、编程等问题继续 CHAT。
