# 已审核知识包：跳过召回与评审

> 后续已基于 PsychQA 合成输入扩充到 12 组标签，其中 8 组可由管理员审核后直用，
> 4 组必须逐次评审。9:1 划分、知识映射及结果见 [psychqa-tag-expansion.md](psychqa-tag-expansion.md)。
> 本文下方“三个知识包”及性能表保留为第一版记录。

## 实际流程

Memory → Supervisor/RouteGuard → KnowledgeAgent：

1. 原有三标签识别通过后，额外检查保守表达白名单及所有近期用户历史。
2. 明确、简单、当前本人的问题才能尝试知识包。未知词、否定、转折、多背景、他人、
   历史/假设、治疗用药、持续加重、建议无效等不能直用；不新增标签识别模型调用。
3. 从数据库确认审批有效、未停用、未过期。Redis 按知识包 ID + 审核版本缓存快照。
4. 逐条读取引用知识，确认 ID、来源、正文及发布状态仍匹配审批快照。
5. 命中：直接使用审批过的完整片段，不做 query embedding、Chroma/BM25、联合评审，
   不扩展未经审批的相邻片段。轨迹记录 `SKIPPED_APPROVED_PACK`，不是 `REVIEWED`。
6. 未审核或功能关闭：沿用原候选缓存/正常 RAG，仍执行模型评审；
   已审核包失效/不可用：正常召回与评审。
7. RiskGuardian 仍运行。如果风险为 MEDIUM/HIGH，清空直用知识、撤销直用状态，
   重新执行一次正常 KnowledgeAgent；保留风险结果，不重复评估，不允许再次命中知识包。
8. Counselor 与最终流式回复按原流程运行。

风险回退在真实 AgentRuntime 调度中共 6 步（Memory、Supervisor、Knowledge、Risk、
Knowledge、Counselor），在原有 8 步限制内。

这是一条小范围快捷路径，不是通用中文语义解析器。单独“失眠”可能包括早醒等情形，
因此直用要求更明确的“睡不着 / 入睡困难 / 难以入睡”；原候选缓存仍可处理“失眠”并进行评审。
复杂表达绕过只影响性能，不拒绝回答。召回评审仍可能降级，其原有状态会传递给回复环节。

## 三个知识包与管理员操作

| ID | 标签 |
|---|---|
| exam-sleep | 考试 / 焦虑 / 入睡困难 |
| exam-focus | 考试 / 焦虑 / 注意力难集中 |
| task-start | 学业任务 / 焦虑 / 拖延启动 |

草稿从内置公开资料 `academic-stress-exam-adjustment.md` 和
`anxiety-grounding-sleep.md` 选择至多 4 个已发布片段，不包含学生会话或记忆。
草稿选择是确定性提示，不等于人工确认这些片段足够完整。

启动新版后进入管理员界面的 **常见问题知识包**：

1. 核对显示的每段原文、适用范围是否包含常见原因、应对建议和限制。
2. 内容不完整或不适合时，先维护来源资料，再刷新；不要确认启用。
3. 勾选“我已核对内容与适用范围”，点击“确认审核并启用 30 天”。
4. 可随时停用。预览后来源发生变化会返回 409，要求重新核对。

数据库表 `reviewed_knowledge_packs` 保存审批快照、审核账号、审核时间、到期时间、
审核版本及乐观锁版本。没有运行启动自动审批，没有把模型评审结果当成人工审批。
当前只保留最近一次审批元数据，不是完整审批历史系统。

接口（均受现有 ADMIN 权限保护）：

- `GET /api/admin/knowledge/packs`：三个草稿/有效包、来源、内容摘要指纹。
- `PUT /api/admin/knowledge/packs/{id}/approve`：`{"digest":"预览返回的 digest"}`；
  审核人从服务端登录身份读取，不接受客户端指定审核人。
- `PUT /api/admin/knowledge/packs/{id}/disable`：停用。

## 缓存和失效

- 总开关：`KNOWLEDGE_REVIEWED_PACKS_ENABLED`，默认 true；无审批时也不会直用。
- Redis：`mindharbor:knowledge:approved-pack:v1:<id>:<revision>`。
- Redis TTL 最长 1800 秒，且不超过审批剩余有效期；审批有效期 30 天。
- Redis 中的内容必须和数据库审批快照一致，缓存不能注入未经审批的正文。
- 每次命中都验证数据库审批状态及引用知识；Redis TTL 不是停用/更新的唯一保护。
- 引用知识删除、重传产生新 ID、正文/来源变化或变为待审核，均失效。
  无关知识变化不要求该知识包重新审核。审批版本和引用内容指纹共同定义包版本。
- Redis 故障、快照异常、数据库校验异常均放弃直用，走正常路径。
- 运行中已取得的有效快照属于本次请求；停用不会撤回已经发往客户端的内容。

## 测试与本地测量（2026-10-20）

自动测试覆盖：

- 三组合及同义表达直用；不调用 recall/review/额外模型；风险评估没有被标记跳过。
- 否定、背景冲突、第三人称、历史、假设、药物、持续加重、建议无效、近期风险绕过。
- 审批前不启用；审核账号/有效期持久化；匿名/学生不能操作。
- 来源修改、删除、撤回、审批过期、管理员停用、Redis 异常/污染、过期预览。
- MEDIUM/HIGH 撤销知识包，正常检索一次；真实 Runtime 在 8 步内完成风险回退。
- 原候选缓存、媒体审批、RouteGuard、Counselor 和既有 Agent 流程回归。

独立本地探针使用真实 Ollama（qwen2.5:1.5b、bge-m3）、Chroma、Redis；
知识来自 MySQL 只读快照，审批只存在测试仓库中。未启动学生聊天、报告、Excel 或邮件任务，
也未在实际业务数据库中审批知识包。测试创建的 Redis 键执行后清理。

## 部署边界

上述探针运行时没有替换旧 Docker 服务，其测量结果不能作为部署成功证明。
源码已更名为 MindHarbor，升级旧 MindBridge 实例时需沿用原数据库、卷与 Chroma collection，
并同步更新独立 MCP 工具服务。部署后检查健康接口与管理员知识包列表；
正式启用直用功能仍需管理员核对并批准内容，不能由部署脚本代为审批。
